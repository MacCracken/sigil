# Security Audit — 3.12.9 (2026-08-14)

**Scope.** Closes the two wider-scope items of the 2026-08-08 forged-signature
issue: the RSA sign / blind / CRT workspace (23 banked globals) and the bignum
engine (17 more), plus `cbank()` exhaustion detection. This audit covers the
localisation's correctness, the zeroization change, and the new API.

**Result: no findings. The audit floor stays empty.**

> This is the second audit filed on 2026-08-14; the first covers 3.12.8's
> `err_*` rename and the toolchain bump. Neither covers **3.12.3–3.12.7**,
> which filed no audit report at all — a five-release lapse that includes
> 3.12.6's RSA-PSS authentication-bypass fix. That range remains
> un-re-verified and is tracked in the roadmap.

## F1 — Shared-lane removal on the sign path (INFO, resolves a real hazard)

40 file-scope banked globals deleted; every buffer is now a function-scope
stack local. Verified: `grep -E '^var (_rsa_|_bn_)' src/` returns nothing, and
`cbank()` has no remaining call site in either `rsa.cyr` or `bignum.cyr`.

**The hazard this removes was not theoretical.** `_rsa_raw_sign`'s Bellcore
verify-after-sign guard ran

```
bn_cmp(schk, sm, limbs)      # schk = &_rsa_sign_chk + bk*512
                             # sm   = &_rsa_sign_m   + bk*512
```

with **both operands in one shared lane** — the same "both operands of the
decision in a single shared object" shape as the v1.5 verify bypass this issue
was filed for (888 forged signatures accepted of 400,000). A lane collision
that left a consistent pair behind would make the guard pass, admitting exactly
the faulty signature it exists to reject. The prior framing — "banked **by
design**, secret residue + per-lane wipe" — recorded the confidentiality
property and missed the integrity one.

**Stack budget checked.** Every function stays well inside the 122,880 B
per-fn cumulative budget: `_rsa_raw_sign` 5,632 B (4.6%), `_rsa_crt_modexp`
3,328 B (2.7%), `bn_mont_modexp` 3,600 B (2.9%), `bn_modinv` 2,048 B (1.7%),
`bn_modexp` 2,048 B (1.7%), `_rsa_gen_blind` and `_rsa_pkcs1v15_sign` 512 B
each. The build emits no new `oversized array local kept in shared global`
note — the only two remain `hash_file_into`'s, unchanged and correctly banked
(see the 3.12.8 audit).

## F2 — Zeroization: per-lane → per-call (INFO, strictly tighter)

`_rsa_scrub_sign_lanes` and `_bn_mont_scrub_lanes` are replaced by
`_rsa_sign_scrub`, `_rsa_crt_scrub`, `_bn_mont_scrub` and `_bn_inv_scrub`,
which wipe the calling frame's own buffers.

Checked:

- **Every return path is covered.** `_rsa_raw_sign` scrubs on all three
  (blinding failure, Bellcore mismatch, success — the success path scrubs
  *after* `bn_to_be` serialises the signature out). `bn_modinv` scrubs on both
  (`done == 3` failure and success). `_rsa_gen_blind` wipes `rand` on all three.
  `_rsa_pkcs1v15_sign` wipes `sem` on both.
- **Widths are the declared buffer sizes, not `limbs`-derived**, so the wipe is
  complete for any key size rather than only the low limbs actually used.
- **The change removes a hazard of its own.** The per-lane wipe zeroed the
  *whole lane*; with two threads aliased, one signer's scrub would zero the
  other's in-flight secret residue mid-sign. Per-call wiping cannot reach
  another frame.
- **No stale scrub targets.** `_rsa_scrub_sign_lanes` also memset the bignum
  engine's `_bn_inv_*` lanes; those globals are deleted and the memsets went
  with the function, so nothing wipes a dead global. (3.12.5 hit exactly that
  failure mode with `_bn_modrem`/`_bn_modn1` and left the globals behind; both
  are now deleted.)
- **Plain `var`, not `secret var`.** All new locals are plain — correct per
  quirk #9 / ADR 0004, and doubly so now that they are genuine stack locals.

## F3 — `cbank()` exhaustion detection (INFO, new API)

`crypto_banks_exhausted()` and `crypto_banks_claimed()` added.

- **Threshold is exact.** `n` is `atomic_fetch_add`'s pre-increment value, so
  lanes are unique for `n` in `0..BANKS-2`; the flag is raised on
  `n >= SIGIL_CRYPTO_BANKS - 1`, which is precisely the first aliased lane.
- **Race-free without a CAS.** The flag is monotonic 0 → 1 and never cleared,
  so concurrent writers all store the same value.
- **Hot path cost is one compare**, inside the already-cold
  first-`cbank()`-per-thread branch — not on the per-operation path at all.
- **Detection, not prevention** — deliberate. A hard abort was considered and
  rejected: a crypto library terminating a long-running server is a worse
  failure mode than a reportable condition, and post-3.12.9 the asymmetric
  stack no longer uses lanes, so exhaustion cannot influence a signature
  verdict. Residual exposure is symmetric/EC scratch, where a collision yields
  a corrupted digest or failed handshake — fail-closed.

## F4 — Test coverage is mutation-proven (INFO)

The issue's own lesson — *"a probe that cannot see the defect is not evidence
of absence"* — was applied rather than quoted.

`tests/tcyr/rsa_lane_race.tcyr` gains a sign group: two threads pinned to
lane 1 via `crypto_bank_set(1)`, 40 signatures each. PKCS#1 v1.5 signing is
deterministic, so all 80 must be byte-identical to the KAT; base blinding draws
a fresh `r` per signature but the unblinded output is unchanged, so any
difference is corruption.

**Mutation result** — re-banking only `sm`/`schk` (the two compare operands):

| | 3.12.9 | mutated |
|---|--:|--:|
| signatures byte-identical to KAT | **80 / 80** | 79 / 80 |
| corrupted or rejected | **0** | 1 |

The 1-in-N shape matches the original report. The test is therefore sensitive
to the specific defect class it guards.

`banking_concurrent.tcyr` gains a lane-exhaustion group (flag clear before,
trips after enough auto-assigning threads, sticky afterwards). It is placed
**last in the file by construction** — it drives lanes into aliasing, so any
banked assertion after it would be racing deliberately.

## F5 — Module-level arrays cost 8× their declared size (INFO, new invariant)

Not a vulnerability, but a sizing invariant nobody in this tree had established,
and it is why the measured saving was 8× the arithmetic.

A **module-level** `var X[N]` allocates N eight-byte slots (8N bytes); a
**function-local** `var X[N]` is N bytes. CLAUDE.md quirk #3 documents only the
local case. Probe-verified under cycc 6.5.21 (`var G[20000]` → 160,000 B), and
confirmed by the codebase: 40 deleted declarations summing to 1,249,280
declared units, × 8 = **9,994,240** — exactly the A/B-measured reduction.

Consequence: every remaining banked global understates its footprint 8× in its
own comment. Filed as [architecture note 003](../architecture/003-global-arrays-are-eight-bytes-per-element.md).

## Audit floor

**Empty.** No CRITICAL, HIGH, MEDIUM or LOW finding carried out of this cycle.

**Follow-on, not a finding:** the symmetric/EC scratch (sha2, hmac, hkdf,
aes-gcm, chacha20-poly1305, ecdsa, ed25519, x25519, argon2, blake2b, tls12_prf)
is still banked — 188 `cbank()` sites across 28 files, and the bulk of the
remaining 785,408 B. Localising it would retire `cbank()` entirely and remove
the 63-lane ceiling from the whole library. Tracked in the roadmap; not scoped
here.
