# Audit — 3.13.11 (2026-10-08)

**Scope.** Not a full pass. This is the cyrius W2 stdlib wave (cyrius `docs/development/roadmap.md`
§ *W2*, 2026-10-08): the toolchain pin moves to cyrius 6.7.5 and the release carries the two issues
filed against sigil since 3.13.9 plus the follow-ups the new pin allows. Everything the W2 survey
found and this release does not fix is in `docs/development/roadmap.md` (the 3.13.11 block at the
top of "Outstanding work"). Changed code:

1. the toolchain pin 6.6.18 → 6.7.5, `cyrius.lock` re-locked (41 rows);
2. `src/privkey.cyr` (`pem_decode_privkey`, new private `_privkey_from_der_kind`) — §F1, §F2;
3. `src/pem.cyr` (`pem_decode_certs`, `pem_decode_certs_into`) — §F2;
4. `src/sys_util.cyr` (`agnosys_run_capture_timeout`'s drain) — §F3;
5. `src/sha256.cyr` / `src/sha384.cyr` (the one-shots) — §F4;
6. comments only: `src/crypto_scratch.cyr` (`_crypto_needs_block`), `tests/threads.cyr`, and the
   cyrius `CVE-NN` citations rewritten to the cyrius ledger's 2026-10-08 ids and labels;
7. tests: `tests/regdump.cyr` (new), `secret_epilogue.tcyr` and `sha_oneshot_wipe.tcyr` (new), new
   groups in `privkey.tcyr` and `pem.tcyr`, and `errno_peer.tcyr`, `ecdsa_sign.tcyr` and `ecdh.tcyr`
   changed — §R1.

**Result: four findings, all fixed in this release** (F1 MEDIUM, F2–F4 LOW), and one test finding
(§R1). Public API unchanged: no signature changed, and the functions cyrius's own `lib/` calls from
the fold keep their names and contracts.

## F1 — `pem_decode_privkey` left the decoded private key in the heap (MEDIUM, fixed)

*Filed 2026-10-05 by cyrius 6.6.16's review of the native TLS server's key load
(`docs/development/issues/archive/2026-10-05-pem-decode-privkey-leaves-the-decoded-key-in-memory.md`).*

**What.** `pem_decode_privkey` base64-decodes the PEM body into `alloc(pem_len)` and parses that
DER. The buffer IS the private key — the EC scalar, the Ed25519 seed, every RSA component — and no
return path wiped it: not the success returns, not the RSA sentinel (which left a fully decoded RSA
key behind and told the caller to retry, decoding it a second time), not the failures after the
decode. The bump allocator never frees or reuses, so each call left a plaintext copy for the life
of the process.

**Severity: MEDIUM** on sigil's scale — a breach of the key-zeroization rule (CLAUDE.md "every
secret buffer overwritten before free"), with no standalone exploit: reading the copy needs a
separate disclosure of the process heap (a core dump, a swapped page, an over-read elsewhere).
Reach: every caller that loads a PEM key, cyrius's native TLS server among them (one copy per
distinct key since cyrius 6.6.16, one per handshake before it).

**Fix.** The typed-parser dispatch moved into `_privkey_from_der_kind`, so one exit zeroes
`pem_len` bytes of the scratch after every decode — success, the PKCS#8 RSA sentinel, every
failure, a failed or partial base64 decode included. A PKCS#1 key with `key_max < RSAK_SIZE` is
RSA by its label, so the sentinel now returns before anything is allocated or decoded. (Behaviour
note: such a key now gets the sentinel even if its body is not valid base64; the retry with an
RSAK-sized buffer reports the malformed body.)

**Test.** `privkey.tcyr` "the DER scratch is wiped on every return": the scratch region is located
from the allocator's next block and scanned after SEC1 P-256, PKCS#8 P-384, PKCS#8 Ed25519, PKCS#1
RSA at both buffer sizes and a body that fails near its end. Against the 3.13.10 source: 119, 180,
47, 1177 and 44 bytes of DER left, and an allocation on the PKCS#1 sentinel path.

## F2 — the PEM scratch allocations were never checked (LOW, fixed)

**What.** `pem_decode_privkey` and `pem_decode_certs` used `alloc(pem_len)` unchecked, and
`pem_decode_certs_into` did not refuse a null `der_pool`, so a refused allocation (address-space
exhaustion, an over-large `pem_len`, a capped arena) decoded through address 0.

**Severity: LOW** — the process dies (fail-closed); nothing is accepted that should not be.

**Fix.** Both allocations are checked and return -1; `_into` refuses `der_pool == 0`.

**Test.** `privkey.tcyr` "a refused scratch allocation" and `pem.tcyr` "a refused pool allocation
and a null pool" cap `ALLOC_MAX` just below `pem_len`; SIGSEGV against the old source, -1 now.
Mutation: with only the `_into` guard removed, the null-pool row segfaults again.

## F3 — the capture drain ignored a refused `O_NONBLOCK` (LOW, fixed)

**What.** `agnosys_run_capture_timeout` set its pipe non-blocking with a raw
`syscall(SYS_FCNTL, …)` pair whose results it ignored — CLAUDE.md's one tracked exception to the
no-raw-syscalls rule. A refused `F_SETFL` left the pipe blocking, so a silent child could hold the
"bounded" drain in `read(2)` past its deadline.

**Fix.** The stdlib's `fd_set_nonblocking` (per-target `O_NONBLOCK`), checked: a refusal kills and
reaps the child's tree and returns Err before any read. The exception is retired and CI's security
scan now fails on any raw `syscall(` in `src/`, `tests/`, `fuzz/`, `programs/` or `benches/` (4 hits
before, 0 after). `errno_peer.tcyr` uses the same wrapper, and so now compiles for agnos.

**Test.** The scan is the regression gate; the refusal itself cannot be provoked on a valid pipe.
`capture_bounded.tcyr` / `subprocess_tree.tcyr` / `errno_peer.tcyr` pass unchanged.

## F4 — `sha256()` / `sha384()` left their context in the dead frame (LOW, fixed)

**What.** The one-shots run on a stack context and never wiped it (`sha512()` has since 3.13.1). Its
final state is the digest and its block buffer the message tail; HMAC hashes a key longer than the
block through these one-shots, so that key's hash stayed behind (roadmap residue item (c)).

**Fix.** Each one-shot zeroes its 144 / 208-byte context with `_sigil_wipe64` before returning. A
`memset` there cost +210 ns on a 64-byte SHA-NI hash; the word wipe costs +24 ns (545 → 569 ns),
and +35 ns on SHA-384 (6966 → 7001 ns), best of 15 on the dev host.

**Test.** `sha_oneshot_wipe.tcyr`: a 64 KB dead-stack scan for the state run and the message, on
the SHA-NI and forced-software paths, with the 3.13.10 one-shots as anti-vacuous controls (they must
be found) and `sha512()` as the green control. 8 of 20 rows red against the old source.

## R1 — lifting quirk #10 had silently disabled the zeroisation tests' register check (fixed)

cyrius 6.6.15 clears the defer walker's save area, so a `secret var` epilogue no longer spills the
return registers into dead stack (CLAUDE.md quirk #10, architecture note 005). New
`secret_epilogue.tcyr` proves it under the 6.7.5 pin: markers in every saved register, a
`secret var` function returning with them, and a window over the released frames — 7 markers in the
secret row and 7 in the plain-`defer` row under cyrius 6.6.14, 0 under 6.7.5, on x86_64 and aarch64
(qemu), with an anti-vacuous control that leaves all eight one frame down.

The same fix disabled a test mechanism. `ecdsa_sign.tcyr` and `ecdh.tcyr` used a `secret var` call
as their register spill ("Test with a spill", note 005), so under ≥ 6.6.15 they no longer saw
registers at all: with the SHA-NI block's register clear deleted, `ecdsa_sign.tcyr` still passed
90 / 0. `tests/regdump.cyr` now stores xmm0–xmm15 and the scratch GPRs (aarch64 q0–q7, x1–x16;
encodings checked with llvm-mc) into the dead stack the groups scan; with the same mutant the
signing group finds 12 words of k. `secret_epilogue.tcyr` carries a row that the dump sees the
vector registers (red if its xmm0 / xmm1 stores are removed).

## Not covered

The SHA compression frames' own locals under HMAC / HKDF (roadmap residue item (b)); the
constant-time question for RSA signing over `src/bignum.cyr`'s carry branches (roadmap, 3.14.0);
`_pem_init`'s three unchecked init-once allocations (roadmap). Real-hardware runs of the new tests
on the pi, ecb, ach and cass are roadmapped; this release ran them on x86_64 and under qemu-aarch64.
